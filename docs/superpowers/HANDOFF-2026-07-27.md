## 4. The ramp blocker — RESOLVED

Both defects were independently reproduced with a dense scan (0.001, not the
0.05 the original tests used), fixed, and **the user approved deviating from the
handoff's published values**. A "Deviations from the design handoff" table is now
at the top of the plan file.

| Handoff value | Now | Why |
|---|---|---|
| Dark ink `#06120c` | `#000000` | `#06120c` only clears 4.5:1 from L = 0.1974 while white clears to L = 0.1833 — a dead band no threshold can fix. Black clears from 0.175, which overlaps. |
| Threshold `0.30` | `0.1833` | The exact WCAG crossover for white. 0.30 failed ~200 of 2001 samples per ramp, worst 3.0:1. |
| `RAMP_CVD` loss stops | rescaled in linear light | The `-0.3` stop was brighter than both `-0.1` and the neutral — a 5.5 L\* inversion. Rescaling preserves chromaticity exactly, so the orange is unchanged, only darker. Drawdown now 0.14 L\*. |

**Correction to the earlier handoff:** it claimed `RAMP_NORMAL` "passes cleanly".
It does not — it sags 0.34 L\* mid-segment, because `rampColor` interpolates in
sRGB while luminance sums gamma-decoded channels, and that decode is convex. At a
third of a JND it is invisible, so `RAMP_NORMAL` was deliberately left unchanged.
The ramp test now asserts monotonicity in CIE L\* against a one-JND bar rather
than strict `>`, because a strict comparison at 0.005 would fail on gamma
convexity rather than on a design error.

Verified in the browser, not just in unit tests: all 20 labelled tiles on `/demo`
clear 4.5:1, worst measured ratio 4.71.

## 5. Five plan defects found and fixed during execution

The plan file has been corrected in place for each, so it and the code agree.

1. **`foregroundFor` ink/threshold** — see section 4.
2. **`RAMP_CVD` stops** — see section 4.
3. **`const displayFont = bodyFont`** (Task 7) would have left `--font-display`
   undefined, silently dropping ~14 `font-display` consumers on the unmigrated
   screens to `system-ui`. `bodyFont.variable` is the *string* `"--font-body"`.
   Fixed with its own `Instrument_Sans` loader call.
4. **`sizeOf` regression** (Task 11) — the plan sized P&L tiles by
   `Math.abs(item.totalPL)`. `Treemap.test.tsx` already asserted the range-aware
   `shares * quote.change`, with a comment warning against exactly this. Kept the
   range-aware metric and added the plan's genuine improvement, the 0.4% floor.
5. **Two wrong test expectations** — the `tile-nav` ragged fixture asserted
   `NEAR` when `FAR` was geometrically closer (fixture widened so it tests the
   ranking rule rather than a 5px accident), and `HeatMapCard` asserted
   `getByText("SIZE")` when the caps are CSS `text-transform`, which never
   reaches the DOM.

Also needed but unmentioned by the plan: `Treemap.test.tsx` and
`HeatMapCard.test.tsx` both need the repo's usual `matchMedia` stub and Nivo ESM
mock. Both are established patterns — copy from `TreemapTooltip.test.tsx`.

  portfolio, which looks exactly like a data bug. Restarting the dev server fixes
  it. This cost real debugging time this session.

  run print duplicate-manual-mock warnings for `firebase-admin` and
  `yahoo-finance2`. Harmless but noisy; `git worktree remove` it when convenient.

  issues.

  sample at 0.005; keep it that way.
